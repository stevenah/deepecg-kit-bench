[ECGBench](https://vajira.info/ECGBench/) catalogues ECG **datasets**: 64 sources with standardised
splits and validated metadata. This site is its counterpart for **models**: every architecture
registered in [DeepECG-Kit]({{ site.kit_repo }}), what it costs, and what has actually been measured
on it.

## How the site stays honest

The catalogue and the numbers come from different places, and neither is typed by hand.

- `_data/registry.json` is generated by importing `deepecgkit` and walking its model and dataset
  registries. Every parameter count, feature dimension and input-length bound on this site comes
  from there.
- `results/snapshots/<id>/` holds the output of `deepecg aggregate` and `deepecg rank` verbatim,
  with a manifest and checksums.
- `_models/*.md` holds prose only. The build **refuses** any page containing a machine fact such as
  `params_total`, so there is never a second copy of a number to go stale.

Because the two are joined on `registry_name`, drift can only appear as a *join failure*, which the
validator catches, rather than as a *value mismatch*, which nothing can catch. Adding an
architecture upstream turns the next registry-refresh pull request red until someone writes its
page.

## Colophon

Jekyll, plain CSS custom properties, and about 120 lines of JavaScript. No framework, no CDN, no
charting library: the charts are SVG generated from the same validated JSON that fills the tables,
inlined so they follow the theme without any script touching them.

Build tooling is Python with a single dependency. PyTorch is needed only to regenerate the registry,
and never runs on the deploy path &mdash; a broken dependency upstream cannot take this site down.
